# 需求文件：Gem v1 完整實作

## 概述
Gem 是一款瀏覽器端 PixiJS 2D 三消益智遊戲。玩家交換相鄰寶石構成三連以上直線，消除並引發連鎖掉落，在限定手數或時間內達成關卡目標。v1 涵蓋 80 關（4 個世界）+ Endless 模式，桌面瀏覽器優先，無付費、無廣告、無體力系統。

## 功能需求

### FR-1：核心三消規則引擎
**使用者故事：** 身為玩家，我想要交換相鄰寶石來構成三連以上的直線，以便消除寶石並獲得分數。

**驗收條件：**
- 棋盤支援可變尺寸（6×6 至 9×9），可配置空格
- 偵測水平與垂直方向的 3+ 同色寶石連線
- 無效交換（不產生消除）被拒絕，並以抖動動畫回饋
- 有效交換消耗一手（手數模式下）
- 重力使寶石下落；新寶石從頂端生成
- 連鎖/cascade 偵測遞迴執行，直到無更多消除為止
- 連鎖倍率公式：`min(1.0 + (chain - 1) × 0.5, 4.0)`，上限 ×4.0
- 所有規則邏輯為純 TypeScript，零瀏覽器/Pixi 依賴

### FR-2：特殊寶石生成
**使用者故事：** 身為玩家，我想要透過更大的消除組合來生成特殊寶石，以便規劃強力的操作。

**驗收條件：**
- 4 連（橫/縱）生成 Line Bomb（方向與連線一致）
- 5 連直線生成 Colour Gem
- T 形或 L 形（5 顆）生成 Area Bomb
- 十字/≥6 連生成 Area Bomb
- 重疊優先序：Colour Gem > Area Bomb > Line Bomb
- 生成位置：交換觸發時在被交換寶石的目標位置；cascade 觸發時在圖案中央格
- 每次交換最多生成一顆特殊寶石（最高優先者勝出）

### FR-3：特殊寶石啟動
**使用者故事：** 身為玩家，我想要啟動特殊寶石來產生強力效果，以便清除棋盤上的大片區域。

**驗收條件：**
- Line Bomb (H)：清除整列；Line Bomb (V)：清除整行
- Area Bomb：清除以自身為中心的 3×3 區域（邊緣自動裁切）
- Colour Gem（交換啟動）：清除棋盤上所有與被交換對象同色的寶石
- Line Bomb / Area Bomb：被動啟動——當相鄰寶石被消除時觸發（cascade 觸發）
- Colour Gem：支援被動啟動；自身被消除時會隨機挑選一種棋盤上現有顏色並清除該色所有寶石
- 所有特殊寶石啟動可破壞 Lock 並摧毀 Generator

### FR-4：特殊寶石組合
**使用者故事：** 身為玩家，我想要將兩顆特殊寶石交換組合，以便觸發壯觀的組合效果。

**驗收條件：**
- Line × Line：十字清除（整列 + 整行）
- Line × Area：3 格寬十字清除
- Area × Area：5×5 大爆炸
- Colour × Line：目標色所有寶石轉為 Line Bomb，依序啟動
- Colour × Area：目標色所有寶石轉為 Area Bomb，依序啟動
- Colour × Colour：清除整個棋盤
- 組合連鎖從當前 chain + 1 起算
- 6 個唯一組合對（對稱：A×B = B×A）

### FR-5：計分系統
**使用者故事：** 身為玩家，我想要清楚的計分系統，以便了解我的操作如何轉換為分數。

**驗收條件：**
- 基礎分數：3 連=60、4 連=120、5 連直線=200、T/L=200、十字/≥6=300
- 連鎖倍率公式套用於每次消除事件
- Cascade 步驟獎勵：每個 cascade sub-step +50
- 特殊寶石啟動：`60 × 清除格數` × 倍率（Colour Gem 額外 +500 基礎分）
- 組合基礎分：Line×Line=3000、Line×Area=4000、Area×Area=5000、Colour×Line=6000、Colour×Area=7000、Colour×Colour=10000
- 剩餘手數獎勵：關卡完成時每剩餘一手 +1000 分

### FR-6：關卡系統與目標
**使用者故事：** 身為玩家，我想要跨越 4 個世界的多樣化關卡目標，以便遊戲保持新鮮感與挑戰性。

**驗收條件：**
- 80 關跨 4 個世界（每世界 20 關），加上 Endless 模式
- 5 種目標類型：分數、清除（blocker）、收集（顏色）、送達（delivery cell）、複合（2+ 組合）
- 手數模式（多數關卡）與計時模式（特定關卡）
- 每關星級評價：1–3 星，基於分數或剩餘手數/時間
- 星門公式：分數基準 ×1.0/×1.6/×2.5；剩餘手數/時間基準有定義的區間
- Gate 關卡需要累積星數才能解鎖
- Boss 關卡（每世界 1 個 + W4 mid-boss）有獨特棋盤形狀與特殊規則
- 關卡規格以型別化 JSON 儲存，包含棋盤、寶石、限制、目標、blocker、星門

### FR-7：Blocker 系統
**使用者故事：** 身為玩家，我想要增加策略深度的 blocker，以便需要仔細規劃我的操作。

**驗收條件：**
- Jelly（遺忘之霧）：覆蓋於格子上，每次該格消除清掉一層（最多 3 層）
- Lock（固化記憶）：寶石不可移動、不可消除；需被特殊寶石爆炸路徑破壞
- Generator（霧源）：每 N 手在相鄰空格生成 jelly 或 lock
- Unstable（不穩定寶石）：6 手倒數；歸零時 3×3 無分清除 + 300 分罰分
- Delivery Cell（送達格）：棋盤底端的目標格，用於 Drop 目標
- 完整的 Blocker × Special 交互矩陣依 GDD §4.6 實作
- 支援堆疊 blocker（如 W4 的 lock + jelly 共存於同格）

### FR-8：棋盤初始化與重洗
**使用者故事：** 身為玩家，我想要棋盤永遠可玩，以便永遠不會卡在無有效操作的狀態。

**驗收條件：**
- 初始棋盤保證：無預存消除 且 至少有 1 組有效交換
- 顏色池隨進度擴展：3 色（L1-L3）→ 最多 7 色（L41+）
- 每關可配置生成權重偏差
- 暗示系統：閒置 5 秒後以微妙脈動動畫標示一組有效交換
- 無有效交換時自動重洗（保留分數與手數）
- 種子化 PRNG（Mulberry32），4 個串流：boardInit、cascadeFill、juice、misc

### FR-9：遊戲流程與狀態機
**使用者故事：** 身為玩家，我想要選單、遊玩、結果之間的流暢轉場，以便體驗感覺精緻。

**驗收條件：**
- 完整狀態機：splash → menu → worldMap → levelSelect → game → levelComplete/levelFail
- 額外狀態：pause、endless、endlessEnd、settings、credits
- 所有轉換透過單一 `transition(from, to)` 函式；禁止直接賦值
- 遊玩中按 ESC 暫停；tab 隱藏時自動暫停（`visibilitychange`）
- Tab 返回時顯示「繼續？」覆蓋層再恢復
- Cascade 必須在關卡結算前完成（永不截斷）
- 關卡完成時播放剩餘手數獎勵動畫（每手 120ms）

### FR-10：Endless 模式
**使用者故事：** 身為完成所有世界的玩家，我想要無盡挑戰模式，以便持續追求高分。

**驗收條件：**
- 完成 L80（世界 4）後解鎖
- 難度依分數 1–15 級遞增（每 5000 分升一級）
- 漸進式：顏色增加（4→7）、blocker 引入、棋盤擴大（7×7→9×9）
- 結束條件：3 次重洗後仍無有效交換、玩家主動退出、或 120 秒無操作
- 本機排行榜：最高分、最長連鎖、最多特殊寶石生成各前 10 名
- 結果存入 `saveState.progress.endlessBest`

### FR-11：存檔系統
**使用者故事：** 身為玩家，我想要進度自動儲存，以便關閉瀏覽器後能繼續遊玩。

**驗收條件：**
- localStorage key `gem.save.v1`，帶版本化 schema
- 追蹤：關卡紀錄（星數、最高分、嘗試次數）、設定、教學進度、Endless 最佳紀錄
- 防抖寫入（500ms），關鍵事件立即寫入（關卡完成、設定變更）
- localStorage 滿/被封鎖時優雅降級（toast 警告，遊戲繼續）
- 版本遷移支援，未知未來版本以 escrow 保存
- 匯出/匯入 JSON；重置需二次確認

### FR-12：輸入系統
**使用者故事：** 身為玩家，我想要用滑鼠、觸控或鍵盤與棋盤互動，以便在任何裝置上都能操作。

**驗收條件：**
- 統一指標抽象，支援滑鼠/觸控/觸控筆
- 兩種交換模式：點擊-點擊 與 拖曳交換（可在設定中配置）
- 完整鍵盤導航：方向鍵移動游標、空白鍵/Enter 選取/交換、ESC 暫停
- Tab/Shift+Tab 進行 UI 焦點循環
- 可配置快捷鍵，儲存於存檔狀態

### FR-13：渲染與視覺回饋
**使用者故事：** 身為玩家，我想要每個操作都有精美的視覺回饋，以便遊戲感覺令人滿足且反應靈敏。

**驗收條件：**
- PixiJS 8，優先 WebGPU，回退 WebGL 2/1
- 圖層階層：背景 → 棋盤（格線/寶石/光暈/特殊/選取）→ 粒子 → 特效 → HUD → UI → DOM 覆蓋層
- 3 種圖形預設：低（30fps 上限、無特效）、中（60fps、光暈）、高（60fps、光暈+泛光+微光）
- 關鍵動畫時序：選取=80ms、交換=200ms、無效抖動=240ms、消除=200ms、cascade 掉落=120ms/行
- 連鎖 ≥3 觸發飽和脈衝（300ms）與全螢幕特效
- 特殊寶石生成：震波效果（600ms）；啟動效果（800ms）
- 粒子系統：基於物件池，依預設上限（100/300/500）

### FR-14：音訊系統
**使用者故事：** 身為玩家，我想要沉浸式音效與自適應音樂，以便音訊增強遊玩體驗。

**驗收條件：**
- 音訊庫：Howler.js（Safari autoplay 處理）
- 透過 splash 畫面的使用者手勢解鎖 autoplay
- SFX 對應遊戲事件：gem.pick、swap.invalid、match.base、chain.stinger、special.spawn 等
- 自適應音樂，以 intensity 驅動的層疊（intensity 0..1）
- 主音量/音樂/SFX 音量控制；全域靜音切換（M 鍵）
- 暫停與 tab 隱藏時暫停音訊；繼續時恢復

### FR-15：設定與無障礙
**使用者故事：** 身為玩家，我想要完整的設定包含無障礙選項，以便自訂符合我需求的體驗。

**驗收條件：**
- 音訊：主音量、音樂、SFX 滑桿 + 靜音切換
- 圖形：預設選擇（低/中/高）+ 減少動態切換
- 無障礙：色盲模式（綠色盲/紅色盲/藍色盲）、高對比、長按確認
- 遊玩：暗示延遲（0=停用）、自動啟動特殊寶石切換
- 語言：支援 zh-TW 與 en；自動偵測瀏覽器語言
- 設定以 DOM 覆蓋層渲染；變更立即儲存
- 首次啟動自動偵測 `prefers-reduced-motion`

### FR-16：UI 畫面
**使用者故事：** 身為玩家，我想要清晰直覺的 UI 畫面對應所有遊戲狀態，以便輕鬆導航遊戲。

**驗收條件：**
- Splash 畫面：載入進度與使用者手勢提示
- 主選單：遊玩、Endless（若已解鎖）、設定、製作人員
- 世界地圖：顯示關卡節點、星數與鎖定狀態
- 關卡選擇卡片：顯示目標、預算與最佳紀錄
- 遊戲 HUD：分數、剩餘手數/時間、目標進度、暫停按鈕
- 關卡完成：星星動畫、分數明細、下一關/重玩/返回選項
- 關卡失敗：鼓勵訊息、重試/退出選項
- 暫停覆蓋層：繼續、重新開始、設定、退出
- 製作人員畫面：捲動內容

### FR-17：新手引導
**使用者故事：** 身為新玩家，我想要透過遊玩自然學會遊戲，以便不需要閱讀說明。

**驗收條件：**
- L1–L3 可在 180 秒內完成，零文字教學
- 預置棋盤有明顯的消除機會
- 閒置 5 秒後顯示暗示（L1：首次為 15 秒）
- 無強制教學對話框或必須點擊的引導
- 教學步驟追蹤器記錄里程碑供遙測使用（非阻塞）
- 教學節奏：每關最多引入 1 個新機制；組合在新機制後 2 關出現

### FR-18：效能與技術需求
**使用者故事：** 身為玩家，我想要遊戲在桌面瀏覽器上流暢運行，以便體驗永不卡頓。

**驗收條件：**
- 目標 60 FPS（最差情況 ≥55 FPS）
- 99 百分位幀時間 ≤25ms；遊戲邏輯 ≤4ms/幀
- Draw calls ≤80/幀；hot path 零 GC 壓力（全部物件池化）
- 初始 bundle ≤5MB gzipped（JS ≤500KB、CSS ≤50KB、核心 atlas ≤3MB、核心音訊 ≤1MB）
- TTI ≤3 秒（寬頻）
- 30 分鐘記憶體漂移 ≤10MB；關卡切換 heap 差異 ≤2MB
- 瀏覽器支援：Chrome、Edge、Firefox、Safari（最新 2 個穩定版）
- 固定時間步遊戲迴圈（60Hz 累加器）搭配插值渲染

### FR-19：確定性與 RNG
**使用者故事：** 身為開發者，我想要遊戲規則在給定種子下完全確定，以便可靠地重播與測試。

**驗收條件：**
- Mulberry32 PRNG，64-bit 種子拆分為 4 個串流
- boardInit、cascadeFill、misc 串流必須跨執行 bit-exact
- juice 串流可 desync（僅視覺隨機性）
- CI 確定性測試：固定種子 + 100 個指令 → 3 次冷啟動產生相同事件日誌
- Cascade 安全上限：每個玩家指令最多 50 個 sub-step

### FR-20：國際化
**使用者故事：** 身為玩家，我想要遊戲使用我的語言，以便理解所有文字與 UI 元素。

**驗收條件：**
- v1 語言：zh-TW（繁體中文）與 en（英文）
- 自動偵測 `navigator.language`；可在設定中手動覆寫
- 所有 UI 文字外部化至 locale JSON 檔案
- BitmapFont atlas 包含 zh-TW 的 CJK 子集
- 語言設定持久化於存檔狀態

## 非功能需求

### NFR-1：模組邊界
- `game/rules/` 必須零依賴 Pixi、DOM、audio、i18n
- `game/level/` 僅依賴 `game/rules`
- `rendering/` 依賴 `game/*` + Pixi；不依賴 DOM 或 audio
- `audio/` 僅依賴 `game/runtime/events`
- `state/` 僅依賴 `game/*` 型別

### NFR-2：建置與部署
- Vite 用於開發伺服器與生產建置
- Vitest 用於單元/整合測試；Playwright 用於 E2E
- ESLint + typescript-eslint + Prettier 確保程式碼品質
- 靜態部署（無後端）；需要 HTTPS
- CI 預算閘門在每次 PR 驗證 bundle 大小

### NFR-3：安全與隱私
- 不收集 PII；僅使用 localStorage
- 所有 CDN 資源需要 HTTPS + SRI hash
- 字型自行託管；不外部載入字型
- 不請求瀏覽器權限（無相機、麥克風、位置、通知）

### NFR-4：離線支援
- Service Worker 快取核心 bundle + 已載入的世界 bundle
- 已載入的世界完全可離線遊玩
- 未載入的世界需要一次連線以快取

## 正確性屬性

### CP-1：棋盤有效性不變式
每次棋盤操作（初始化、消除、cascade、重洗）後，棋盤必須滿足：無預存 3+ 消除 且 至少存在一組有效交換（否則觸發重洗）。

### CP-2：分數單調性
遊玩期間玩家分數必須單調非遞減，除了 Unstable 寶石爆炸罰分（−300，下限為 0）。

### CP-3：連鎖倍率邊界
對任何 chain count ≥1，連鎖倍率必須始終在 [1.0, 4.0] 範圍內。

### CP-4：手數計數一致性
手數僅在有效交換或直接特殊寶石啟動時遞減一次；無效交換、cascade、暗示、重洗永不遞減手數。

### CP-5：Cascade 完成保證
一旦有效交換被提交，產生的 cascade 必須完整執行完畢後才進行關卡結算。resolving 期間的時間/手數耗盡不得截斷 cascade。

### CP-6：特殊寶石優先序確定性
給定相同棋盤狀態與消除圖案，特殊寶石生成必須始終產生相同類型與位置（確定性 tie-breaking）。

### CP-7：狀態機轉換合法性
每次狀態轉換必須遵循合法轉換表。除 worldMap→worldMap（世界切換）外，無狀態可轉換至自身。`pause.previous` 僅能是 `game` 或 `endless`。`settings.returnTo` 不能是 `settings`。

### CP-8：RNG 確定性
給定相同種子與指令序列，規則引擎必須跨多次執行產生 bit-exact 相同的事件日誌（排除 juice 串流事件）。

### CP-9：組合對稱性
對任意兩顆特殊寶石 A 與 B，combo(A,B) 必須產生與 combo(B,A) 相同的效果。

### CP-10：Blocker 層級完整性
單一清除事件對一個 jelly 格僅移除恰好 1 層，無論同一 tick 內有多少重疊清除來源命中該格。
